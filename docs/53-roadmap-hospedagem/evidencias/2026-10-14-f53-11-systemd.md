# F53-11 — unidades systemd

Data: 2026-10-14 (UTC). PR #81, merge `d064e26`.

## Validação local

Comando executado no checkout baseado em `origin/main`, com imagem
`python:3.12-slim` e cache de pip:

```sh
MSYS_NO_PATHCONV=1 docker run --rm -v "<checkout-origin-main>:/src:ro" -v or-pip-cache:/root/.cache/pip python:3.12-slim sh -c "cp -r /src /w && cd /w && pip install -q -r requirements-dev.txt 2>/dev/null && pip install -q --no-deps . 2>/dev/null && pytest -q -p no:cacheprovider tests/backend/test_systemd_units.py"
```

Saída literal:

```text
2 failed, 6 passed, 1 skipped in 0.13s
```

As duas falhas vieram de fins de linha CRLF: neste checkout Windows
`core.autocrlf=true` gravou `infra/systemd/run-opportunity-radar-window` com
CRLF e o `sh` do `python:3.12-slim` retornou `set: Illegal option -`. O
wrapper em `main` usa apenas `set -eu` (não há `set -o pipefail`). O blob no
git já era LF; o CI Linux do GitHub não é afetado (checks do PR #81 verdes,
abaixo).

## Reexecução após a correção do `.gitattributes`

Correção: `.gitattributes` com `infra/systemd/* text eol=lf` e `*.sh text
eol=lf`; `infra/systemd` recriado no working tree (`file` mostra o wrapper como
`POSIX shell script, ASCII text executable`, sem CRLF). Mesmo comando, com
`-v "$(pwd -W):/src:ro"`:

```text
8 passed, 1 skipped in 0.10s
```

As unidades não estão instaladas em nenhuma VM. Os critérios AC01–AC05 são
externos e permanecem sem prova de VM.
